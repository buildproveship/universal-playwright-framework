# First-party imported adapter v1 — RRDSCRUM-207

Candidate entry: `@releaseready/playwright-framework/adapter/imported-v1`. This is a trusted first-party normal-UI bridge, not a sandbox for arbitrary customer Node code. It does not create case reviews, prepared data receipts, or run approvals.

`ImportedExecutionRequest` separates the frozen source selection (`selection.runId`, `selection.revision`) from the actual execution (`run.id`, attempt exactly one). Its observation binds the existing source case UUID/revision/digest, canonical source ID, exact product repository commit, application/environment configuration versions, artifact manifest and observed closure hashes, framework commit/implementation hash, and explicit data policy/requirements hashes. App version/build, owned loopback target receipt, prepared input receipt, configuration digest and expiring per-run approval are exact pins.

The trusted composition supplies a separate exact review/approval context and a fixed `RegisteredImportedArtifact`. That registry must verify the sealed source/build/support/resolved-dependency closure and implement only the independently reviewed product bridge. Unknown artifacts are unavailable. The callback is never accepted from a request body or customer repository configuration.

The mandatory `beforeAcquire` callback performs one fresh parent admission immediately before browser launch. It must revalidate current review, revocation, authorization, prepared data, app version and ownership. Immutable artifacts are checked before admission and again immediately before bridge loading. Scenario expiry and cancellation are checked after asynchronous admission; late completion cannot acquire a browser. A worker that acquired anything is single-use. The parent process supervisor must prove child exit and complete cleanup before releasing the shared admission reservation.

The borrowed browser uses the existing lifecycle and same-origin request guard. Routing overrides are unavailable because page routes can outrank context guards. Fault-injection and restart cases are outside this initial normal-UI policy. The bridge must claim exactly the selected existing source ID once, and return exactly one completed case with bounded step/hook status evidence. Unknown cleanup, failed hooks, blocked transport, extra/mismatched cases, pending/undefined steps or incomplete evidence cannot pass. Cancellation may leave context shutdown acknowledgement unknown even after browser close; that uncertainty is retained, never promoted to confirmed cleanup.

The implementation digest is a deliberately reviewed candidate pin, not a founder case approval. The new tests use explicitly synthetic authority/targets and do not authorize or execute genuine imported product cases. Historical evidence validation checks the exact stored request and case correspondence without replay or upgrading historical results to today's framework revision.
